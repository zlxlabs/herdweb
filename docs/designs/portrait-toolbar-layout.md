# 设计：竖屏底部工具栏布局与语音作曲器单手操作

**状态**：已落地并真机验收通过（2026-08-22 用户 iPhone 经 Tailscale debug 实例实测，Mic 居中版定案）；剩余可选项仅悬浮胶囊化
**日期**：2026-08-22
**Base**：2b1d348

## 问题

竖屏手机上，底部工具栏默认 8 个按钮（`Esc`、`C-c`、`⌫`、`⏎`、`✥`、`⌨`、`🖼`、`☰ More`），
启用语音后自动注入第 9 个 `voice-input`。按 `styles/base.css:86-93` 的约束
（每钮最小 44px + 4px 间距），9 钮 ≈ 428px，超过常见竖屏宽度（390px），
只能靠 `overflow-x: auto` 横向滚动才能看全——对「监控 + 干预」工具来说，
滚出视野的按钮等于不存在。

语音作曲器另有单手操作问题：Mic 按钮（48px 圆形）位于底部动作行最左端，
是右手持机时拇指最难够的角落，而它恰是最高频按钮；录音中的停止目标与开始同尺寸，
只是变红。

## 使用形态前提

用户的默认形态是**软键盘收起**（`mobile.keyboardMode` 的意义所在）：
输入与移动尽量走 remobi 自带能力（语音作曲器、d-pad、工具栏），
软键盘只是逃生舱而非常驻件，以此最大化终端可视面积。
因此「⌫/⏎ 软键盘自带所以冗余」的论证不成立——必须按键盘收起形态重新排频率。

## 频率分析（键盘收起形态）

| 动作 | 频率 | 现有落点 |
|---|---|---|
| 语音输入 | 最高 | 🎤（注入位） |
| ⏎ 确认（审批、发送） | 极高 | 工具栏、d-pad |
| Esc / C-c 打断 | 高 | 仅工具栏 |
| 方向键（审批菜单） | 高 | ✥ d-pad |
| 图片 drop | 中 | 🖼 |
| ⌫ 删改 | 低 | 工具栏、d-pad、作曲器 textarea |
| ⌨ 唤起软键盘 | 低（逃生舱） | 工具栏 |
| 其余（Tab、Ctrl 组合、tmux 管理） | 低 | ☰ drawer |

两个关键事实：

1. **d-pad 浮层自带 ⌫ 和 ⏎**——✥ 开着时，方向键 + ⌫ + ⏎ 构成键盘收起形态下的
   完整编辑套件。⌫ 砍掉后的第二落点是 d-pad，不是软键盘。
2. **文本编辑主战场是作曲器 textarea**——语音说错词，正确动线是在 composer 里
   改完再发，而不是发出去再在终端里 ⌫。成立的话，终端级 ⌫ 只剩 shell 场景，
   交给 d-pad / ⌨ 逃生舱即可。

## 设计决策

### row1 默认布局：8 钮、图标化、两分区

```
Esc  C-c  ✥  ⏎  │  🎤  🖼  ⌨  ☰
 控制键（终端主权）  输入与模式（拇指热区）
```

- **砍 ⌫**：第二落点是 d-pad 的 ⌫ 与作曲器 textarea。
- **⏎ 保留**：键盘收起形态下它是审批 Agent 的第一动作，频率太高不能埋。
- **C-c 保留**：需支持连点两下退出 Agent，埋进任何第二层都会出事。
- **⌨ 保留但定位为逃生舱**：必须在第一层永远可达——drawer 虽不依赖键盘可打开，
  但键盘状态机出问题时逃生舱不能埋。
- **🎤 升格为默认一等公民**：语音是主输入方式，不再是 `asr.enabled` 才注入的
  补丁位；ASR 不可用时应隐藏而非占位。位置从「插在 keyboard-toggle 后」
  （`src/config.ts:123-152`）挪到右侧输入区。
- **图标化**：Esc、C-c 保留文字（学 moshi，这两个图标化反而看不懂）；
  其余全图标；`☰ More` 去掉文字只留 ☰。8 钮 ≈ 380px，390px 竖屏刚好不滚。

横向滚动保留为配置层逃生门（用户自定义超宽时兜底），但默认体验不滚。

### 语音作曲器单手布局

- Mic 从最左端挪出拇指死角：候选方案为「居中放大（64px+，微信语音式）」
  或「右置」；Send 保持右下。两版做出来真机对比后定。
- 录音中停止目标应比开始更大更显眼（现在只是变红，尺寸不变，
  `styles/base.css:299-303`）。

### 记录但不做的方向

1. **工具栏与 composer 互斥值得重申**：现在开 composer 隐藏整条工具栏
   （`styles/base.css:161`）。键盘收起形态下「边听输出边按住说话、说完顺手 ⏎」
   是连贯动作，不该有模式切换。改动大，单独立项。
2. **悬浮胶囊栏**（moshi 式不贴底边）：纯视觉，可做可不做。
3. **作曲器作为主输入面的编辑体验**（光标定位、改词、重发）：textarea 聚焦
   会唤起软键盘，但这是局部临时键盘，与「终端上方常驻半屏键盘」不矛盾。

## 落地顺序

1. row1 默认砍 ⌫ + 图标化 + 重排分区 + 🎤 挪位（defaults + CSS，低风险）
2. composer 的 Mic/Send 单手布局两版真机对比
3. （可选）悬浮胶囊化
