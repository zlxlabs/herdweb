## 问题陈述（用户原声）

在手机用 herdr 的场景里，语音输入非常重要、非常方便。像 moshi 一样原生引入 ASR 支持。
架构上支持多服务商，前期只接豆包 ASR（火山引擎大模型流式语音识别）。

参照：moshi（原生 iOS）四引擎（Parakeet 端侧 / Apple SpeechAnalyzer / 本地 Whisper / 云端），
语音被定位为 "non-negotiable"。remobi 是浏览器 PWA，moshi 的端侧引擎路径在浏览器里不存在。

## 关键约束（已验证，含出处）

- 豆包双向流式 ASR：`wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`，边听边出字；
  增量 0 spike 实测 Node HTTP 101、PCM 上行和 0x9 partial/final 下行，详见
  `docs/sessions/260819-1306-asr-spike-results.md`。
- 浏览器 WebSocket 不能自定义握手 header，因此采用 **query 参数鉴权**：
  `api_key` + `api_resource_id`，resource 为 `volc.seedasr.sauc.duration`；header 鉴权仅作
  对照组实测，不是浏览器路径（结论同见上述 spike 结果文档）。
- 部署形态：单人自部署（Tailscale https），页面访问者 = 完全信任（README 既有安全模型），
  密钥下发浏览器可接受（用户已裁决，C8），文档写明口径即可。
- iOS PWA（主屏幕 standalone）getUserMedia 受限（firt.dev 兼容表）；Safari 标签页内可用；
  Android Chrome PWA 正常。能力检测 + 按钮降级是基线，不是扩展。
- getUserMedia 需 secure context；`remobi serve` 只出 HTTP → 该功能依赖 Tailscale Serve /
  反代 https 这一前置（C2），写进 README。
- remobi 现状杠杆：sendData 注入链、dpad 按钮模式、gesture lock、.local 配置（密钥不进 git，
  cli.ts:205）、CSP 构建器（serve.ts:154-169）、happy-dom/playwright 测试模式。
- 已核实的代码事实：hook 是 fail-open（hooks/registry.ts:111-113，hook 抛错仅 log 后放行），
  不能当安全闸门；send() 在 WS 未 OPEN 时仅入内存队列（client-entry.ts:207-213），无送达确认。

## 选定方案：豆包浏览器直连

音频不经过 remobi 服务端：浏览器采集 → 直连火山 wss（query 鉴权）→ 识别文本在浏览器本地
走现有 sendData 链路注入终端。**服务端改动 = 两个 header（connect-src +
permissions-policy）+ 一个静态资源路由（AudioWorklet bundle，R10）+ 纯校验层**
（config schema/types/merge，R4）。
无 WS 协议扩展、无二进制音频通道、无 server-only 密钥机制。

```
 手机浏览器(PWA)                          火山引擎
 ┌─────────────────────────────┐
 │ toolbar 作曲器入口 ─▶ composer │ （只开二层，不自动录音）
 │              │ 点 Mic start/stop │
 │              ▼              │
 │   AsrEngine(provider接口)    │
 │     └─ doubao: 音频采集       │── wss(query鉴权) ──▶ openspeech.bytedance.com
 │         PCM管线(重采样/量化)  │◀── 流式 partial/final ───┐
 │              │ onText       │                          │
 │              ▼              │                          │
 │  二层作曲器(编辑/发送) ──▶ sanitize(R1) ─▶ sendData ─▶ WS(input帧) ─▶ PTY
 └─────────────────────────────┘
```

## tap-to-toggle 状态机（R8，迁移表为基线；细节 eng review 交付）

```
idle ──tap──▶ permission-requesting ──start──▶ connecting ──ws open──▶ recording
  ▲             │ cancel                         │ fail                    │ tap/
  │                       ▼                               ▼                     ▼
  │                     error ◀─── asr error frame ───────┴── ws 断连 ◀── stopping ──▶ waiting-final
  │                       │                                                     │        │ final / 3s超时
  │                       │                                                     │        ▼
  └─────── 确认/取消 ─────┴─────────────────── preview ◀────────────────────────┘
  任意状态 ──visibilitychange hidden / audio interruption(R2)──▶ cancelled ──▶ idle
  permission-requesting/connecting 中再次 tap 一律 cancel 回 idle；recording 中 tap 停止并等待 final
  preview/error 中 tap Mic 无效果，必须先确认或取消 preview
  waiting-final 中 WS 断连：按 error 迁移，已识别文本保留在 preview 可手动发送
  重复/乱序 final：序号 ≤ 已应用序号则丢弃，否则覆盖 preview 文本（不追加）
```

## 错误路径（零静默失败，全部为验收标准）

getUserMedia 拒绝/不可用、非 secure context、**WS 握手拒绝**（401/403 发生在 upgrade 前，
浏览器只给通用 error、拿不到 X-Tt-Logid，文案引导查密钥/网络——v5 Codex #9）、
录音中断网（WiFi↔蜂窝切换高发）、**协议错误帧 0xF 与业务错误帧 0x9**（0x9 带 logid）、空结果（不注入不回车）、
锁屏/切后台 tap 事件丢失（visibilitychange 兜底）、**音频会话被来电/Siri/其它 App 中断
（R2：按 cancelled 迁移，按钮复位+提示）**、停止后尾包延迟（waiting-final + 3s 超时）、
AudioWorklet 异常。增量 1 只通过引擎 `onError` 提供错误回调；按钮可见状态、用户提示与
console 结构化事件（asr:connect/first-partial/final/error）属于增量 2 的 UI 责任边界。


在增量 2 接线前，`src/asr/` 是包内源码，不提供 npm `./asr` 公共入口；当前发布边界仅
交付 worklet 资产与 ASR 配置类型，禁止为没有第二消费者的引擎实现增加 export。

### E1（原开放题 1）：AudioWorklet 交付路径

- `build.ts` 新增 `bundleWorkletAsset()`，镜像 `bundleClientAssets` 的双路径：
  源码运行时 esbuild 现打；发布安装走 `readPrebuiltAsset('asr-worklet.js')`（build.ts:31-47 既有模式）
- `scripts/build-overlay.ts` 加写 `dist/asr-worklet.js`；`files[]` 已含 `dist/`，发布链路零改动
- `serve.ts` 新增路由 `GET {basePath}asr-worklet.js` → `text/javascript`，
  `cache-control: no-cache`；不接入 `?v={version}`，由 no-cache 策略避免旧 worklet 复用。
- **CSP 零改动**：same-origin worklet 走 script-src 族（script-src-elem，v5 Codex #14 修正），`'self'` 已覆盖
  （serve.ts:162 既有 header 验证过）。blob: 被否的理由消失，不引入 `'unsafe-inline'`/`blob:`

### E2（原开放题 2）：采集与背压

- **不手写重采样器**：`new AudioContext({ sampleRate: 16000 })` 由浏览器内部重采样
  （Layer 1 内建；Safari 14.1+）。spike 加一项探针：目标机 AudioContext 实际输出采样率，
  若不遵守 16k 则回退 pcm.ts 线性抽取（实现留接口，默认路径不建）
- pcm.ts：Float32→Int16 量化 + 100ms 分块（1600 样本/包，3200B）
- **背压闭环**（v5 Codex #6，从简实现）：在途总量 = worklet MessagePort 在途 + 应用环形缓冲
  + `ws.bufferedAmount`；每个 100ms tick 检查，高水位 2s → `onError('network-too-slow')`
  可见错误（**不静默丢音频**——丢音频=识别缺字=静默失败）；不建 drain 调度；
  WS CLOSING/CLOSED 立即停止采集并转 error；stop 顺序 = 停采集 → 排空缓冲 → 发尾包
- 尾包（v5 Codex #7/#8）：worklet 按 1600 样本攒包；stop 时 worklet 先 flush 残留为末包
  （flush/ack：主线程收到末包后才发结束包），消除 128-frame quantum 与 100ms 包的乱序窗口；
  SAUC 结束包 flags 有 0b0010（无序列）/0b0011（带序列）两种 variant、payload offset 不同，
  以 spike 实帧为准锁死 → waiting-final，3s 超时

### E3（原开放题 3）：状态机实现

- mic-controller 单一 `state` 字段 + 显式 transition 函数（禁散写赋值）
- 计时器：connect 5s 超时、waiting-final 3s 超时
- final 去重键：会话内单调 appliedSeq，序号 ≤ appliedSeq 丢弃，否则覆盖 preview
- 连续 tap：connecting 中取消、recording 中停止，preview/error 中忽略（不排队）

### E4（原开放题 4）：mock ASR endpoint 覆盖范围

`tests/fixtures/asr/mock-volc-server.ts`（node ws）：握手鉴权校验（query 参数缺/错 → 401 帧）、
full client request → full server response、每 N 个音频包回 partial、负序号包 → final、
可注入畸形帧/错误码/断连。fixture 驱动（增量 0 录的真帧），覆盖引擎全链路集成测试。

### E5（原开放题 5）：音频中断检测信号

多信号 OR：`MediaStreamTrack.onended` + `track.onmute` + `AudioContext.statechange` +
`visibilitychange`。spike 附带观察 iOS 实际触发哪个信号，实现按最保守（任一触发即 cancelled）。

### E6：预览输入框 × 键盘主权 — REVOKED（v5，Codex #13 纠正）

原判断「预览 input 需要键盘主权白名单」基于错误前提：键盘抑制只作用于终端自己的
textarea（client-entry.ts:94-105 `setKeyboardSuppressed`），普通 preview `<input>`

## Eng Review v5 — Codex 第 2 轮吸收（16/16，2026-08-19）

上文已就地修订（E6 撤销、E7 渲染层特判、E2 背压闭环/尾包 flush-ack、E1 CSP 措辞、
错误路径三类、测试矩阵 e2e 行）。其余落定如下：

- **#1 注入连接状态**：client-entry 向 overlay 暴露终端 WS 连接状态（isConnected /
  onConnectionChange）；mic-controller 注入前检查，非 OPEN → 文本留预览 + 提示，
  **不走 send() 的内存队列**（队列会在重连后偷发）
- **#3 会话 epoch**：mic-controller 维护 generation 计数；getUserMedia/WS/timeout 等所有
  异步回调捕获 gen，失配即丢弃并 stop tracks（getUserMedia 无取消信号）
- **#4 中断信号修正**：`track.onended` → cancelled；`track.onmute` → 观察（unmute 恢复，
  5s 超时 cancel）；`AudioContext.statechange` 仅在 state 为 interrupted/非主动 suspended
  时处理（正常 suspended→running 与主动 close 不触发 cancelled）；spike 观察 iOS 实信号
- **#5 AudioContext 构造**：`new AudioContext({sampleRate:16000})` 包 try/catch
  （NotSupportedError）+ 构造后 sampleRate 校验，双保险；失败回退 pcm.ts 线性抽取
- **#10 golden bytes**：协议单测断言独立于实现的 golden（spike 实帧）：byte1/2 nibble、
  big-endian payload 长度、gzip 解压后 JSON、PCM s16le；mock 与生产 encode/decode 不互相证明
- **#12 sanitize 顺序**：voice 路径 = beforeSendData hooks → sanitize → sendData；sanitize
  正向放行 `\n`/`\t`、剥离 `\r` 及其余控制/格式分隔符，是所有变换之后的最后一道（防
  fail-open hook 重新引入 `\r`/C0）
- **#15 发布包冒烟**：增量 1 加 `pnpm pack` → 临时目录安装 → `node dist/cli.mjs serve` →
  请求 `{basePath}asr-worklet.js` 的冒烟测试（防 readPrebuiltAsset 动态 fallback
  掩盖 dist 缺资产；esbuild 是 devDependency）
- **#16 校验值 redact**：config-validate 对 asr 子树 redact 字符串原值；测试覆盖
  父对象被字符串替换的路径（如 `doubao: "sk-xxx"`），不只叶子字段
- **spike 验收追加**：SAUC 尾包 variant（0b0010/0b0011）实帧锁定；握手拒绝/0xF/0x9
  三类错误的实际表现记录进帧格式备忘
