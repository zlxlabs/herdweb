**结论：先让几个关键决策动作在真机上可靠到达 agent，再扩展键盘能力。** 手机端的核心问题是：用户看到“回答问题”等提示后，能否迅速找到并送出正确操作。意图按钮方向对，但先做少量固定入口即可；三套完整映射和自动识别现在偏早。直接调用语义操作更根本，但当前链路只有向 PTY 写入字节的接口，尚无这类契约。([代码](/tmp/consult-repo/src/session.ts:242))

1. **编码**：方向键可试传统 xterm 修饰序列；Shift+Tab 已有 `CSI Z`。不要把 `CSI 1;m X` 套到 Enter、Tab 和全部 F 键。Shift+Enter 需验证扩展序列或沿用现有长按发送 Ctrl+J；Alt+↑需比较修饰方向键序列与 ESC 前缀。CSI u／kitty 是否生效，取决于 herdr 和内层程序的协商、透传与解析，不能仅凭规范选定。([xterm 规范](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)、[kitty 规范](https://sw.kovidgoyal.net/kitty/keyboard-protocol/))

2. **探针**：在真机记录浏览器发出的字节、herdr 收到的字节、内层 pane 收到的字节和 agent 实际动作；分别测直连与嵌套、程序启动前后，并记录版本、`TERM` 和协商状态。仅在替身程序里读到字节，不能证明真实 agent 会执行。

3. **切键集与优先级**：现有目标摘要没有活动 pane 的 agent 类型，先提供手动选择并醒目显示当前选择。优先修复 Shift 被静默忽略，以及抽屉 Ctrl 无回调、贴滞 Ctrl 可能双发的问题；随后验证“回答问题”Alt+↑，补齐批准／拒绝、数字选项和回看入口。最近使用、分步宏、默认增加第二排均后置。([组合键](/tmp/consult-repo/src/controls/combo-picker.ts:145)、[抽屉](/tmp/consult-repo/src/drawer/drawer.ts:104)、[目标摘要](/tmp/consult-repo/src/session-protocol.ts:97))

**最大风险**是按钮标着某个意图，实际却在错误的 pane、错误的终端模式或错误的对话状态发送了另一种输入。当前仓库比远端主线落后 3 个提交；上述代码判断以此工作区为准，herdr 透传行为仍未知。
