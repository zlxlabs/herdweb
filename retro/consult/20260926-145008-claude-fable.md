核实完毕。我对照了 types、combo-picker、toolbar、drawer、floating-buttons、registry、config、session-protocol、dpad 及 docs/designs 下的相关设计记录；herdr 源码在工作目录之外，无法读取，涉及 herdr 透传的判断均为推断。

**核实结论（与材料的出入）**

- sticky Ctrl 两处 bug 在代码层均成立。`createTermBridge` 的 onData 直接转发 xterm 的 onData（client-entry.ts:205），所以 :1131 的原样转发器与 toolbar.ts:57 的 sticky 监听器对同一次输入都会触发，会先发字母再发控制字节。toggleCtrlModifier 只在 toolbar.ts:175 传入；drawer.ts:104-112 和 floating-buttons.ts:61-69 都没传，且 buttonEl 只在 toolbar.ts:225 赋值，而默认 Ctrl 在 drawer（config.ts:284-290），registry.ts:189-195 遇到缺失回调时静默 focus，等于死按钮。
- Shift 静默丢弃属实（combo-picker.ts:158-159）。dpad 已经有正确的 Shift+Tab 字节 `\x1b[Z`，说明知识存在但没集中。
- herdr 不暴露 agent 类型：TargetSummary 只有 id/name/processState/capabilities（session-protocol.ts:97-105）。但 notify 通道已接收外部产生的 asking/done 事件，且带 session 字段（notify/events.ts:1-56），这是现成的"agent 正在提问"信号源。
- 材料未提的一点：按钮发送走 sendData 原始字节，完全绕开 xterm.js 的按键编码器。所以编码问题只取决于 herdr 如何处理入站字节和内层 agent 启用了什么协议，与 xterm.js 无关。

**1. 本质与方案是否对路**

本质是带宽错配：agent 把几十个低频快捷键塞进物理键盘的修饰键空间，而手机只有触屏和 IME。要搬的不是键，而是手机上真正会做的十来个决策。意图层方向对，但"每 agent 一套映射 + 跟随 pane 切换"是过度设计的部分：模式状态在手机上不可见，错模式发错键的代价比多摆几个按钮高得多。#98 已经证明了正确做法：不追 Shift+Enter 的编码，直接用 `\n` 表达"换行不提交"的意图。更根本的解法是三层：薄的纯函数编码层是底座；意图只做"默认按钮预设"，不做运行时抽象；如果 herdr 归你控制，让它把 pane 的 agent 类型和 asking 状态推出来，比在 herdweb 猜要根本得多。

**2. 编码层判断**

- 默认发 legacy xterm `CSI 1;m X`。crossterm、ink 的 keypress 解析器都认它；kitty 和 CSI u 必须由内层 agent 先向终端发启用序列，且 herdr 要么支持要么透传，两个未知叠加，不能当默认。
- Alt+Up 应发 `\x1b[1;3A` 而非 ESC 前缀形式。ESC 前缀在 WS 到 pty 的链路上可能被拆包，拆开后前半个就是一次 Esc 键，对把 Esc Esc 当和弦的 Codex 是实害。Alt+Up 最可能断在 herdr 自身的 Alt+方向键绑定（tmux 类工具常用于切 pane），其次才是 agent 不认。
- Shift+Enter 在无 modifyOtherKeys 或 CSI u 时根本没有 legacy 编码，最可能断在"agent 没启用协议因为 herdr 没宣告支持"。既然 `\n` 已解决，建议不再追。
- 探针设计：在 herdr pane 里跑一个 raw 模式读 stdin 并打印十六进制和时间戳的小脚本，而不是看 agent 反应。矩阵三维：候选序列 × 读者是否先发 kitty/modifyOtherKeys 启用序列 × 是否分两条 WS 消息发送。前者回答透传与改写，中者回答 herdr 是否会重新编码，后者回答拆包风险。最后再用真 agent 各验一遍端到端。

**3. 按 agent 切键集**

自动识别不值得做，最小形态是不切换：drawer 加一个 Agent 分区，三行各三四个按钮，标签直接写 Codex/Claude/Pi。十个按钮换来零模式状态。若 herdr 可改，第二步才是让 target-status 带 agent 字段，届时只高亮对应行，仍不隐藏其他行。

**4. 优先级与遗漏**

- 第 0 步正确，但要把 Shift 丢弃修复并入，它是正确性 bug 不是功能。
- 漏了最高价值且零编码风险的一项：数字和 y/n。Claude Code 权限框、Codex 审批都靠 1/2/3、y/n 加 Enter，现在要唤软键盘。加一行"1 2 3 y n"即可。
- Esc Esc 不需要分步宏，双击现有 Esc 按钮就是两次独立按键。宏整项可砍。
- Ctrl+T、Ctrl+O、Ctrl+G 等单字符 Ctrl 现有 applyCtrl 已能编码，直接做成按钮，不依赖探针。
- F1-F12 等探针结论再定；F8 语音在手机上无意义，你有自己的作曲器。
- 砍掉 combo 最近使用和钉选：单用户工具里钉选就是改 defineConfig。
- 回看已有 PgUp/PgDn、手势滚动和 herdr scrollback editor，不用再加。

**5. 最大风险**

先建编码层再做探针，结果发现 herdr 改写或 agent 不认，白干。探针必须是设计门槛。其次是 ESC 开头序列的拆包，它会把一次组合键变成一次 Esc 加一串垃圾字符，且难以复现。第三是 sticky Ctrl 的双发 bug 已在往 agent 输入框漏字母，应最先修。

**未知项**：herdr 的入站键处理、自身 Alt 绑定、对 kitty 或 modifyOtherKeys 的支持均未核实；三家 agent 当前版本解析器的具体行为也未从源码确认。
